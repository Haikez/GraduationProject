## 1. 参数主要来自哪里

默认配置为 `channels=48`，进入树后实际通道数为 `C=96`；树有 3 个节点，每个节点有 4 个互不共享的 `MambaTCNTemporal`，合计 **12 个时间块**。每个时间块含 2 层 TCN、1 个 Mamba 分支和一个融合门。以下按 `mamba_backend=torch`、12→12 预测、参数对象去重后的常规统计口径计算：

| 模块 | PEMS08（170 节点） | PEMS04（307 节点） | 说明 |
|---|---:|---:|---|
| 12 个 Mamba 分支 | 817,920 | 817,920 | 每块 68,160；含输入/输出投影、状态参数等 |
| 12 个双层 TCN | 670,464 | 670,464 | 每块 55,872；卷积为 96→96 |
| 12 个融合门与 Mamba 归一化 | 224,640 | 224,640 | 门 222,336，归一化 2,304 |
| 6 个跨序列注意力 | 223,488 | 223,488 | 每个树节点 2 个 |
| 3 个 DGCN 模块 | 104,841 | 144,297 | 含节点记忆，随节点数增长 |
| 树记忆张量 | 195,840 | 353,664 | `memory3` 未被前向使用，但仍计入参数 |
| 时间嵌入、输入层、GLU、输出层 | 56,124 | 56,124 | 相对较小 |
| **总计** | **2,293,317** | **2,490,597** | 计算值，待训练环境实例化核对 |

时间块合计占 PEMS08 总参数约 **74.7%**、PEMS04 约 **68.8%**。所以最有效的常规减参手段是缩小通道数，而不是先减少注意力头数；头数变化通常不改变注意力投影的参数量。`memory3` 分别有 48,960 和 88,416 个参数，但当前前向并未使用；清理它能缩小模型文件，预计对训练速度帮助有限，且会改变旧检查点键名。

## 2. 为什么参数不算特别多却训练慢

参数量与训练耗时不是同一指标。当前前向中，12 个时间块会触发 12 次非融合的 PyTorch Mamba 计算；其中状态递推在 Python 中逐时间步循环。每次前向还会调用 DGCN **12 次**，每次都构造 `B×N×N` 的稠密邻接矩阵并做 `topk`，随后仍以稠密张量传播。PEMS04 的 `N²` 规模约为 PEMS08 的 **3.26 倍**，因此节点数增加 8.6% 的参数量，图计算量却可能增加更多。六个跨序列注意力调用、逐轮验证和数据搬运也可能产生耗时。各部分的真实占比应在训练 GPU 上用 [PyTorch Profiler](https://docs.pytorch.org/docs/stable/profiler) 测量，不能仅凭参数量推断。

## 3. 推荐的优化顺序

### A. 先做不改变模型目标函数的加速

1. 在实际训练 GPU 上取 PEMS08 和 PEMS04 各 20–50 个训练 batch，跳过前几批预热，记录前向、反向、图生成、Mamba 分支、验证耗时及峰值显存。用相同 batch 和精度口径比较前后速度。
2. 优先整理 `Graph_Generator.forward`：先求一次 `x_sum = x.sum(-1)`，然后两张图的计算都复用它。原第一项 `einsum("bcnt,cm->bnm", x, memory)` 可改写为 `einsum("bcn,cm->bnm", x_sum, memory)`；原第二项也使用同一个 `x_sum`。代数上等价，浮点求和次序可能造成微小差异；先核对输出和反向梯度，再计时。此改动避免重复求和，并使第一项不必在节点对计算中保留时间维。
3. 用 profiler 判断逐轮验证是否占明显时间。若明显，可把验证间隔统一改为 5 轮，并保留训练结束后对最佳验证检查点的一次性测试；最佳轮次的选择精度会下降，需记录该规则。统一早停也可减少无效尾部轮数，但所有变体和基线须采用同一预定规则。
4. 在支持的 GPU 上单独试验 BF16 自动混合精度；比较若干批的损失、梯度有限性、吞吐和峰值显存，再决定是否纳入正式矩阵。BasicTS 当前训练配置有 `model_dtype` 支持，但现有 MambaTCNCA CLI 尚未暴露此选项；递推状态的数值稳定性必须实测。[PyTorch AMP 文档](https://docs.pytorch.org/docs/stable/accelerator/amp.html)说明了自动转换与精度策略。不要把 FP32 和 BF16 结果混在一个种子统计中。

### B. 用现有命令行缩小模型

以下为理论参数量，均保留 TCN、Mamba、跨序列注意力和 DGCN，不预设精度变化或速度收益：

| 配置 | PEMS08 | PEMS04 | 相对默认减参 |
|---|---:|---:|---:|
| 默认：`channels=48, expand=2, tcn_layers=2` | 2,293,317 | 2,490,597 | — |
| **首选：`channels=32`，其余默认** | **1,111,093** | **1,242,613** | **约 50–52%** |
| `channels=32, expand=1` | 915,253 | 1,046,773 | 约 58–60% |
| `channels=32, expand=1, tcn_layers=1` | 765,493 | 897,013 | 约 64–67% |
| 更激进：`channels=24`，其余默认 | 676,653 | 775,293 | 约 69–70% |

先试 `--channels 32`，它改动单一、参数下降最大且保留结构；若验证集 MAE 接近，再试 `--mamba-expand 1`。只有 profiler 证实 TCN 占显著时间且前两档仍太慢时，再试 `--tcn-layers 1`。降低 `mamba-d-state` 从 16 到 8，在默认 PEMS08 上仅减少约 55,296 个参数（约 2.4%），不宜作为第一步。仅减少 `attention-heads` 不会明显减参。

示例命令：

```bash
PYTHONPATH=src python -m basicts.models.MambaTCNCA.train --dataset PEMS08 --variant full --channels 32 --mamba-expand 2 --tcn-layers 2 --mamba-backend torch --epochs 300 --batch-size 16 --seed 0 --gpus 0 --checkpoint-dir checkpoints/MambaTCNCADG/PEMS08_full_c32_s0
```

### C. 较大结构改动，最后考虑

四个时间块在同一树节点内共享权重，理论上可把时间块从 12 套降为 3 套；PEMS08 总参数约降至 101 万。但四个调用位置输入分布与功能不同，权重共享可能损害表达能力，应作为**新的结构实验**，不能直接视作默认模型的无损压缩。类似地，减少 DGCN 调用次数、改变图稀疏方式或删除一个树层都会改变方法定义，需要重新做消融。当前 `topk` 保留 80% 的边，却继续使用稠密矩阵；单纯调小 `k` 不保证加速，除非后续传播也真正使用稀疏计算。

## 4. 最小验证矩阵与选择规则

先保留现有默认配置的一组 PEMS08/PEMS04 结果作参照。接着只在 PEMS08 上比较默认、`channels=32`、`channels=32+expand=1`：各跑短时同批量计时和完整的**验证集**训练，不看测试集来选压缩配置。若 `channels=32` 的验证 MAE 与默认差异接近随机波动，则用种子 0、1、2 复核，并记录每轮秒数、停止轮次和峰值显存。选定配置后，在 PEMS04 重做，并在同一宽度与精度模式下重新运行三个 `without_*` 消融；不能把默认宽度的消融直接用于解释压缩模型。

建议预先约定可接受的取舍，例如“验证 MAE 不劣于默认超过 1%，且实测训练时间至少减少 25%”；这只是研究决策阈值，不是已观测结果。若精度有明显损失，则回到默认宽度，优先采用第 3A 节的运行时优化。
